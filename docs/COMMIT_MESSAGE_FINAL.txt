Stabilize Life AB Test verification while hardening its local UI surface

The Life AB Test MVP now uses a formalized in-process test suite,
adds explicit input validation, separates UI orchestration from the
simulation pipeline, and replaces string-based result rendering with
DOM-node construction to reduce regression and injection risk.

This keeps the current MVP behavior intact while improving confidence
scoring semantics, input normalization safety, and maintainability of
the app’s execution path.

Constraint: Current Windows environment raises EPERM when relying on `node --test` process spawning directly
Constraint: Must preserve the local MVP flow and avoid adding unnecessary dependencies
Rejected: Vitest migration | unnecessary dependency increase for the current local MVP
Rejected: Keep UI string-based rendering with escaping only | weaker long-term safety than DOM-node construction
